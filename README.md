# Speed Rivals — Neon Circuit

Juego arcade de carreras para dos jugadores en el mismo teclado. Está hecho con HTML, CSS y JavaScript; no requiere instalación ni build, así que puede publicarse como sitio estático.

## Cómo jugar
- Piloto 1: **A/D** o **←/→** para moverse, **W** o **↑** para turbo.
- Piloto 2: **J/L** para moverse, **I** para turbo.
- Evita los vehículos de tráfico durante 60 segundos. La distancia más alta gana.

## Publicar
1. Abre el repositorio `proyecto12`.
2. Entra en **Settings → Pages**.
3. En **Build and deployment**, selecciona **Deploy from a branch**, rama `main`, carpeta `/ (root)`, y guarda.
4. Espera a que GitHub Pages publique el sitio. También puedes importar el repositorio en Vercel y usar los valores predeterminados para un sitio estático.

## Activar el ranking compartido con Supabase
El juego funciona como demo aunque Supabase no esté configurado. Para que los resultados se guarden y se vean desde otros dispositivos:

1. Crea un proyecto en Supabase.
2. En **SQL Editor**, ejecuta este SQL para crear la tabla y las políticas de demostración:

```sql
create table if not exists public.race_results (
  id bigint generated by default as identity primary key,
  winner text not null,
  distance numeric not null default 0,
  player_one text not null,
  player_two text not null,
  created_at timestamptz not null default now()
);

alter table public.race_results enable row level security;

grant select, insert on public.race_results to anon;

create policy "Anyone can read race results"
on public.race_results for select
to anon
using (true);

create policy "Anyone can add race results"
on public.race_results for insert
to anon
with check (
  char_length(winner) between 1 and 16
  and char_length(player_one) between 1 and 16
  and char_length(player_two) between 1 and 16
  and distance >= 0
);
```

3. En **Project Connect** o **Settings → API Keys**, copia la URL del proyecto y la **publishable key**.
4. Abre `index.html` y reemplaza `PEGA_AQUI_LA_URL_DE_SUPABASE` y `PEGA_AQUI_LA_PUBLISHABLE_KEY` por esos dos valores.
5. Guarda el cambio en GitHub. No uses una **secret key** ni la publiques en el navegador. Las políticas anteriores son para una demo pública de clase: cualquiera puede leer el ranking y enviar resultados.
